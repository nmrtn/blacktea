Spending controls for AI agents

Your agent can pay. You decide how much.

Black Tea sits between an AI agent and its wallet. A policy file sets the limits, a human approves what falls outside them, and every approval leaves a receipt. Open source. SDK, CLI and MCP server.

What it stops

Three things an agent with a wallet gets wrong, or gets talked into.

  1. 01

    The price changes after you said yes.

    An approval is bound to the exact request. A higher amount, another payee, another network or another token at settle time is refused before anything is signed.

  2. 02

    Many small payments add up to a large one.

    would_spend counts what was already paid, in total, per wallet or per host, before it allows the next one.

  3. 03

    The same approval is used twice.

    A held payment can be completed once. A replayed, altered or expired approval never reaches the wallet.

The policy is a file

Rules run top to bottom, first match wins. They are checked in code, outside the prompt, so the model cannot argue with them. 

// policy.json
{
  "rules": [
    { "if": { "wallet_in": "./blocklist.txt" },
      "then": { "reject": "blocked_wallet" } },
    { "if": { "would_spend": { "window_hours": 24, "gte": 50 } },
      "then": { "reject": "daily_cap" } },
    { "if": { "amount_lt": 5 },
      "then": { "approve": true } }
  ],
  "default": { "approval": "callback" }
}

Three ways in

One codebase. Pick the one your agent can reach.

  1. sdk

    A function your agent calls.

    import { blacktea } from "@nmrtn/blacktea";
import { x402Wallet } from "@nmrtn/blacktea/adapters";

const pay = blacktea({
  policy: "./policy.json",
  source: x402Wallet({
    privateKey: process.env.EVM_PRIVATE_KEY,
    chain: "base",
  }),
});

const { data, receipt } = await pay({
  url: "https://api.transcripts.example/v1/NVDA/q3",
  intent: "earnings call transcript",
  trigger: "What did Nvidia say about export limits?",
});
  2. cli

    A command for agents with a shell.

    $ blacktea pay --url https://api.transcripts.example/v1/NVDA/q3 \
    --intent "earnings call transcript" --max-amount 20
$ blacktea approvals show --last 10
  3. mcp

    A server for Claude Desktop, Cursor and other MCP clients.

    When a payment needs you, the assistant asks in the chat and pays only after you say yes. 

    { "mcpServers": { "blacktea": {
    "command": "npx",
    "args": ["-y", "@nmrtn/blacktea-mcp"],
    "env": {
      "EVM_PRIVATE_KEY": "0x...",
      "BLACKTEA_POLICY": "/path/to/policy.json"
    }
} } }

What it is not

Worth knowing before you install it.

  1. 01

    Not a wallet.

    You bring the key. Black Tea decides whether it gets used.

  2. 02

    Not a hosted service.

    It is a library that runs in your process. There is no account and nothing to sign up for. Where approvals are sent, Slack or anything else, is your code.

  3. 03

    One rail today.

    x402, which pays for HTTP resources in USDC on Base. The rail is an interface; cards and bank transfers are not built.
